# UI 重设计方案（桌面 / 手机）

> 本文是路由界面重新设计的目标蓝图与决策记录，供实现时对照。
> 最后更新：2026-08

---

## 0. 设计动机

现有 UI 的问题：

1. **按数据模型组织，而非按用户任务组织**：用户要回答"我想用这个模型，现在能用吗"，但 UI 让用户先选分组 → 再配 Vendor → 再看逻辑模型 → 展开 Key 才能看到映射与健康。
2. **入口太多，职责重叠**：发送栏有 `[⚡]`（Quick Actions）、`[≡]`（控制台）、`[🎲]`（手动路由）三个按钮，旧侧栏还有一个面板。用户不知道点哪个。
3. **健康状态藏在深处**：熔断/冷却状态需要"展开 Vendor → 展开 Key → 看模型 pill"才可见。核心信息不可达。
4. **ui.ts 是巨石**（1194 行），难以维护。
5. **手机端完全没设计**：侧栏三栏在手机上不可用。

**核心原则**：「我想用这个模型，现在能用吗？」这个问题应在 1 秒内被回答。所有其他功能是次要配置。

## 1. 入口策略

### 1.1 统一入口：Quick Actions 菜单顶部

不再保留独立的控制台发送栏按钮 `[≡]`。控制台入口放到 Quick Actions 下拉菜单的**最顶部**：

```
发送栏 [⚡] 按钮
  └── 点击弹出 Quick Actions 菜单
       ├── 🗂️ 路由控制台      ← 新加，置顶
       ├── ⚙️ 设置            ← 管理便捷方案
       ├── 📄 查看日志         ← 日志查看
       ├── ───────────
       ├── ⚡ DeepSeek V3     ← 已有的快捷方案
       └── ...
```

### 1.2 保留的独立按钮

- `[🎲]` 手动路由按钮：保留在发送栏，功能独立（锁定下一次路由到指定 Vendor/Key/Model），不整合进控制台。
- 旧侧栏面板按钮：保留兼容入口，但不再主动引导用户使用。

### 1.3 入口对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| 独立 `[≡]` 按钮 | 一步直达 | 发送栏拥挤，按钮多 |
| **Quick Actions 顶部** ✅ | 少一个按钮，Quick Actions 已成路由中心 | 多一步点击（先点 `[⚡]` 再点"路由控制台"） |

选择 QA 顶部的原因是：控制台不是日常高频操作（日常切模型用 Quick Actions 方案就够了），多一步可以接受。

### 8.7 连接状态：启动置空地址占位（已完成，2026-08）

**问题**：拦截模式不写 `oai_settings`，导致 ST「自动连接上次服务器」可能连到上次路由/手动配置的 vendor。

**方案**：`initQuickerApi` 调 `ensureEmptyConnectionPlaceholder()`：把连接置为 **custom + 空 URL + 空 model** + `saveSettingsDebounced()`，并 `setOnlineStatus('Valid')`。
- 持久化空地址 → 下次启动 `isValidUrl('')` false，RA_autoconnect 无 target 可连（治本）
- source=custom 同时切断 RA_autoconnect 的 deepseek 分支
- 只改 oai_settings + 下拉显示，**不 trigger('change')**（避免 reconnect / /v1/models）
- 真实连接由拦截模式（`patchGenerateData`）生成时接管
