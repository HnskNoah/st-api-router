# UI 重设计方案（桌面 / 手机）

> 分支：`ui-redesign`。本文是路由界面重新设计的目标蓝图与决策记录，供实现时对照。
> 最后更新：2026-08

---

## 0. 设计动机

现有 UI（`src/routing/ui.ts` 及其内部渲染）的问题是：

1. **按数据模型组织，而非按用户任务组织**：用户要回答"我想用这个模型，现在能用吗"，但 UI 让用户先选分组 → 再配 Vendor → 再看逻辑模型 → 展开 Key 才能看到映射与健康。
2. **健康状态藏在深处**：熔断/冷却状态需要"展开 Vendor → 展开 Key → 看模型 pill"才可见。核心信息不可达。
3. **映射复杂度高**：已归类/未归类双折叠 + 全局搜索，认知负担重；且是日常设置混在主界面。
4. **ui.ts 是巨石**（1633 行闭包），难以维护。
5. **手机端完全没设计**：侧栏三栏在手机上不可用。

**核心原则**：@"我想用这个模型，现在能用吗？"这个问题应在 1 秒内被回答。所有其他功能是次要配置。

## 1. 桌面端：三栏浮层面板

ST 侧栏空间金贵，路由配置的复杂度不该挤在里面。改为**点击按钮弹出的浮层**（类似 Quick Actions 管理器风格），三栏并列。

### 1.1 左栏：逻辑模型仪表盘（核心视图，用户每天看的）

```
┌─────────────────────────────────────┐
│  🔍 搜索模型...                      │
│                                      │
│  🟢 DeepSeek V3      硅基流动 · 主号 │
│     3 条可用路由，最优延迟 1.2s      │
│                                      │
│  🟡 Gemini 2.5 Pro   谷歌 · 备用    │
│     2 条路由，1 条冷却中 (剩余 3m)   │
│     ⚠️ 主号模型不可用，已切备用      │
│                                      │
│  🔴 GPT-4o           无可用路由      │
│     ⚠️ 所有 Vendor 均不可用         │
│                                      │
│  ⚪ Claude 3.5       未配置          │
│     添加 Key 即可开始使用            │
└─────────────────────────────────────┘
```

- 每个逻辑模型一行，显示**综合健康状态** + 当前最优路由 + 关键诊断
- 🟢 正常 / 🟡 有降级 / 🔴 不可用 / ⚪ 未配置
- 不强迫理解 Vendor/Key/Mapping 概念即可用

### 1.2 中栏：路由详情（选中逻辑模型后展开）

```
┌─────────────────────────────────────┐
│  ← 返回  DeepSeek V3                │
│                                     │
│  ── 可用路由 ──                     │
│  🟢 硅基流动 · 主号   3s 冷却       │
│  🟢 硅基流动 · 备用   权重 1.0     │
│  🟡 DeepSeek 官方 · K1 冷却中 2m   │
│     [手动恢复]                      │
│  🔴 硅基流动 · 测试号  余额不足     │
│     [手动恢复]                      │
│                                     │
│  ── 最近失败记录 ──                 │
│  10:23:45  硅基流动·主号  timeout   │

└─────────────────────────────────────┘
```

- 健康状态**默认可见**（无需展开 Vendor/Key）
- 路由按健康排序；冷却/不可恢复直接显示剩余时间 + 手动恢复按钮
- 保留最近失败记录（诊断）

### 1.3 右栏：管理面板（可折叠 / 切换）

```
┌─────────────────────────────────────┐
│  [路由设置]  [Vendor管理]  [导入导出] │
│                                      │

```

- Vendor 管理独立成**可折叠配置区**，不抢占主视图
- 每个 Key 旁显示**成功率进度条**

## 2. 手机端：底部弹出面板（Bottom Sheet）

手机侧栏不可行。改用**底部弹出面板** + 手势操作。

### 2.1 常态：底部一行 + 上滑手柄

```

│                      │
│    (主聊天界面)       │
│                      │
│   ┌──────────────┐   │
│   │  ⚡ 路由状态  │   │  ← 轻触切换
│   └──────────────┘   │
│  ┌────────────────┐  │
│  │                │  │
│  │  底部面板上滑   │  │  ← 拖动手柄
```

- 底部始终显示：当前逻辑模型名 + 健康圆点（🟢🟡🔴）
- 点一下快速切换模型；上滑展开完整面板

### 2.2 展开面板（简化，隐藏高级概念）

### 2.5 桌面 vs 手机差异

| 方面 | 桌面（三栏） | 手机（底部面板） |
|---|---|---|
| 入口 | 侧栏按钮 | 左下浮动圆点 + 底部上滑 |
| 布局 | 三栏并列 | 单列堆叠，全屏高度 |
| 分组 | 显示，可切换 | 隐藏（默认单分组） |
| Vendor 管理 | 右栏折叠区 | 设置页内折叠 |
| Key 编辑 | 内联输入框 | 单独弹窗 |
| 健康状态 | 每模型一行 | 模型名 + 圆点 |
| 路由详情 | 中栏展开 | 独立页面，可返回 |
| 手势 | 点击 | 上滑面板 + 底部 tab |

**共同原则**（不分设备）：
- 模型优先：入口永远是"想用哪个模型，现在能用吗"
- 健康状态默认可见（🟢🟡🔴）
- 冷却恢复最多点两次
- 配置管理退居其次

## 3. 模型映射区（独立设置页，配合新功能）

> 已在 `ui-redesign` 分支实现基础版（`mapping-tools.ts`：批量规则 / 忽略 / 一键归类）。本文为该区完整设计。

**原则**：映射是一次性设置任务，日常界面完全消失；但设置过程对几百个模型也要友好。

```
┌──────────────────────────────────────────┐
│  模型映射  (在设置面板里，不是主界面)      │
│                                          │
│  ┌─ 自动归类 ──────────────────────────┐ │
│  │  「一键归类所有未映射的模型」按钮     │ │
│  │  按核心名归并，5 秒做完              │ │
│  └──────────────────────────────────────┘ │
│  ── 批量规则 ──                          │
│  ┌────────────────────────────────────┐  │
│  │  /kimi\|k3/i  →  kimi-k3   [⚡][✏][🗑] │ │
│  │  （点击会出现实时预览与目标选择）    │  │
│  └────────────────────────────────────┘  │
│  [+ 添加规则]                            │
│                                          │
│  ── 已映射 (23 个) ──                   │
│  │ Vendor │ 真实模型        │ 逻辑     │ │
│  │ 硅基   │ deepseek-chat  │ DS3      │ │
│  │ 谷歌   │ gemini-2.0     │ GN2      │ │
│  │ 硅基   │ deepseek-reason│ DS4      │ │
│  │ ...（表格，分页/搜索/虚拟滚动）      │ │
│                                          │
│  ── 未映射 (3 个) ──                    │
│  ├─ xxx-embedding-v3  [忽略]  [归类]    │
│  ├─ xxx-reranker      [忽略]  [归类]    │
│  └─ test-model-foo    [忽略]  [归类]    │
│  ── 已忽略 ──                           │
│  ├─ xxx-embedding-v3/xxx-reranker（可取消）│
└──────────────────────────────────────────┘
```

### 3.1 兜底"永不遗漏"

```
第一层：核心名精确匹配 → 有现成逻辑模型，直接建映射
第二层：canonical 归并 → 核心名一致但写法不同，归到同一逻辑模型
第三层：兜底新建 → 归不上且不特殊，自动建新逻辑模型（用原模型名）

→ 结果：每个真实模型不是"已归类"就是"已忽略"，没有第三种状态
```

主界面顶部常驻计数胶囊：`⚠️ 还有 N 个模型未归类 [一键归类]`（跨所有 Vendor）。

### 3.2 模型数量多时的处理

1. **默认只显示"能聊天的"**：embedding/reranker/search/thinking/image/cache 特殊变体在拉取时自动丢进"已忽略"，不在主列表。
2. **表格分页 + 虚拟滚动**：默认每页 50，搜索按 真实模型名 / vendor / 逻辑模型 过滤；"只显示未忽略 / 显示全部"切换。
3. **批量操作**：勾选多行 → "归类到所选逻辑模型 / 合并到已选 / 忽略"。
4. **异常数量提示**：某 vendor 拉取 >200 模型时提示"聚合源，建议批量忽略或正则归类"。

### 3.3 手动批量规则（已实现）

- 正则 + 目标逻辑模型；填正则先**实时预览"将影响 N 个模型"**再应用
- **全量语义**：命中即改（用户写 `kimi|k3 → kimi-k3` = 所有含 kimi/k3 的模型都归过去）
- 默认作用于当前 vendor 的所有 key；可勾选应用到所有 vendor 同名模型
- **持久化**（`mappingRules` 字段），区别于只在拉取时生效的 `matchPattern` 自动归类

## 4. 与现状的关键差异（已知差距）

| 方面 | 现状 | 目标 |
|---|---|---|
| 布局 | 侧栏垂直三段 | 三栏浮层面板（桌面）/ 底部面板（手机） |
| 健康状态 | 展开 Vendor→Key→pill | 仪表盘直显 + 路由详情默认可见 |
| 用户入口 | 先分组→Vendor→逻辑模型 | 先看模型状态→详情→配置 |
| Vendor 管理 | 与路由混在一起 | 独立配置区 |
| 冷却恢复 | Key 展开区深处按钮 | 路由详情一键恢复 |
| 错误诊断 | 仅 toastr 一闪 | 路由详情保留失败记录 |
| 映射 | 主界面折叠多区 | 独立设置页 + 规则/忽略/一键归类 |
| 手机 | 无 | Bottom Sheet 专设计 |

## 5. 实现建议

- 依托 `ui-redesign` 分支，ui.ts 巨石已开始拆（`mapping-tools.ts` 为首个独立模块），后续按 vendor/model/group/actions 继续拆。
- domain 纯函数先行（已具备：健康、候选、熔断、映射规则/忽略），UI 是薄适配层。
- 桌面三栏浮层可复用手动路由/快捷按钮的浮层样式与 `Popup` 体系。
- 手机端可先用 Web 端响应式实现（ST 是浏览器），再做拖拽句柄。

## 6. 刻意不做

- ❌ 全屏拖拽/图形化映射（过度设计）
- ❌ 实时 websocket 连接测试（违反约束）
- ❌ SVG 拓扑图（好看但无用）
